## What it is

A maze-building tower defense — **your towers ARE the walls.** Tap an empty cell on an 8×14 grid to build one; enemies always take the shortest currently-*open* path from the top of the board to your core, so every placement reshapes their route. You can never fully seal the core off — a path must always stay open. Waves escalate forever; core HP hits 0 and the run ends.

This is Yev's July 21, 2026 ask — "tower defense with maze building elements, roguelike elements that after every run I get a little stronger, and an endgame where the game gets easier and easier at first but then harder in late game. Thinking Underdark on mobile and Hades on consoles" — un-benching **B3 (maze-builder TD)** from `docs/brief.md`'s not-picked list, the same new-signal path that turned benched A2 flick golf into [Black Hole in One](../black-hole-in-one/README.md).

**Iteration 1 was deliberately core-loop-only**, tighter than the questionnaire's own MVP slice: no meta-progression, no permanent tree, no cross-run currency, no persistence. It earned a **Keep** verdict same day, and **iteration 2** (also July 21) built the "stronger every run" roguelike layer — the whole reason Yev pitched this — plus fixed two UX complaints and rebalanced the towers. Iteration 2 also earned a **Keep**, with the upgrade loop confirmed landing and the pause/build fixes confirmed resolved — but Volt Coil (the upgrade-tree-unlocked 3rd tower) wasn't visible at all until unlocked, reading as a bug rather than a gated feature. **Iteration 3** (also July 21) was a presentation-only polish pass — Yev's ask was clarity and less text, not new systems — and it also earned a **Keep**, with all four legibility questions landing as intended. Its free space surfaced the next real work: a help/pause modal UX bug, the laptop tower-picker's width, wanting to drop the "Mirror" naming, and the headline signal that the game maxes out and feels too easy fast with little replayability — scoped in [Iteration 4 Direction](../../archive/questionnaires/maze-warden-iteration-4-direction.md) into three individually-verdicted passes. **Iteration 4** (also July 21) shipped the first of those three: the help/pause modal fix, the laptop sheet-width cap, and the "Mirror" → "Upgrades" rename — all bugfix/wording, no economy or combat numbers touched. **Iteration 5** (also July 21) shipped the second: a 🧨 **Breaker** enemy that got blocked, then attacked an adjacent tower — the pick that structurally answers "too easy" rather than just retuning numbers. Yev's own playtest found it effectively unreachable: trapping one required a redundant loop/fork maze that `wouldSeal()`'s spawn-always-open guarantee and a normal single-corridor layout never produce. **Same-day revision** replaced it entirely with 💣 **Bomber** — a fuse-based self-destruct that doesn't depend on maze topology at all: left alone, it detonates on a timer and damages every tower in its blast radius, no trapping required. **Iteration 6** (also July 21) shipped the third pass, targeting the iteration-3 playtest's headline complaint directly: the Upgrades tree's rank caps went 3→5 with a new 6th node (🛡️ Reinforced Walls, tower HP), pushing the essence needed to max the whole tree from ~76 to 266 (well-under-10 runs → roughly 34); and the late-game wave curve, which used to flatten once `waveEnemySpeed` hit its hard cap around wave 37, now keeps escalating past that point on all three scaling knobs (count, hp, speed) instead of plateauing. Agent-verified (UI/regression checks plus a simulation of the actual shipped formulas); Yev's own multi-run playtest read landed **Meh** the same day — the tree/curve depth wasn't the actual fix, because the complaint traced to the **in-run gold economy**, untouched by iteration 6. **Iteration 7** (also July 21) shipped the gold-sink fix: every tower placed a run makes the next one's construction cost ~5% pricier (initial placement only — upgrades and sell refunds unaffected), meant to give a maxed-out late-game maze somewhere for its growing gold surplus to go. Bundled in was a Bomber tower-damage bug Yev flagged in the same pass — root-caused as **working as intended, not a defect**: a Bomber's HP matches a regular grunt's, so tower fire in a well-defended maze reliably kills it before its fuse expires; the detonation mechanic itself checks out correct when a Bomber does survive to blow up. Agent-verified via a debug hook, a live multi-wave simulation, and the actual production UI; Yev's own fresh playtest read — and the promotion call it gates — is the remaining confirmation.

## How it plays

- **Tap an empty cell to build a tower.** Three types: 🟦 **Pulse Spire** (long range, single-target focus fire, 25g), 🟪 **Frost Prism** (short range, big splash + heavy slow on a group, 40g), and 🟡 **Volt Coil** (cheap, very rapid low-damage chip damage, 15g — unlocked via ⬡ Upgrades). Tap a built tower to upgrade (2 levels) or sell (60% refund) — including mid-wave, while enemies are active. Tapping a built tower also draws a dashed range ring in its color (iteration 3) — a quick visual answer to "what can this actually hit." **On desktop (iteration 4)**, the build/tower-action sheet is capped to the same ~420px column width it uses on mobile, centered, instead of stretching edge-to-edge.
- **Building costs more the more you've built this run (iteration 7)** — each new tower placed (any type, cumulative for the run) makes the *next* one's construction cost ~5% pricier; a gold sink for the late-game surplus a maxed-out maze otherwise had nothing to spend on. Only initial placement inflates — upgrading an already-built tower or selling one is unaffected, and a sold tower always refunds 60% of what you actually paid for it, not a recalculated current price.
- **Volt Coil shows as a locked slot until unlocked (iteration 3)**, greyed out with a 🔒 icon and an "Unlock in ⬡ Upgrades" hint, instead of being omitted from the build sheet entirely — iteration 2 hid it outright, which read as a missing/broken feature in playtesting rather than a gated one.
- **Game speed toggle (iteration 3)** — a topbar button cycles 0.5x → 1x → 2x → 3x → 0.5x, scaling the whole simulation uniformly (persisted in `localStorage`). Answers the iteration-2 free-space ask for a way to skip past slow stretches without being stuck waiting.
- **Placement that would fully seal the core is rejected** — a "🚧 Path must stay open" toast, no build. Enemies A*/BFS the shortest open route to the core and re-path immediately (via a distance flow-field, recomputed on every build/sell) whenever you change the maze — even enemies already mid-corridor reroute cleanly, never getting stuck.
- **Waves are endless and escalate forever** — enemy count, HP, and speed all scale with wave number (tuning knobs flagged in `PLAYTEST.md`). Board is fully at rest between waves — no timer pressure, tap "▶ Start Wave" when ready. Kills pay gold; clearing a wave pays a bonus.
- **Core has HP; a leak costs 1 HP.** Core at 0 → game over, showing wave reached, enemies defeated, and Essence earned this run, with a restart button and a button into ⬡ Upgrades.
- **A wave-progress bar (iteration 3)** shows resolved/total enemies for the current wave, plus a plain "👾 N left" count, replacing iteration 2's ambiguous "2 + 5 left" (alive vs. queued — a distinction that isn't meaningful to a player).
- **⬡ Upgrades (iteration 2; renamed from "🔮 Mirror of the Warden" in iteration 4; deepened in iteration 6)** — dying banks Essence (`floor(wave/2)+floor(kills/10)`); spend it on 6 permanent-upgrade nodes, `localStorage`-persisted across runs: 💰 Deep Pockets (+10 start gold/rank), ❤️ Fortified Core (+3 start HP/rank), 🔨 Cheap Walls (-10% tower cost/rank), ⚡ Overcharge (+15% tower damage/rank), 🛡️ Reinforced Walls (+12% tower HP/rank, new in iteration 6), and 🟡 Volt Coil (unlocks the 3rd tower). Open it any time via the topbar ⬡ icon or from the game-over screen. The rename dropped the Hades-adjacent "Mirror of Night" framing in favor of a plain, lore-light name matching the game's abstract/neon look (Q4=A) — internal names (`META_KEY`, `meta`, `META_NODES`) are unchanged, not player-facing. **Flagged in iteration 3's playtest as maxing out in well under 10 runs (~70 essence for the whole tree) — iteration 6 raised the four original nodes' rank caps 3→5 and added Reinforced Walls, taking the full-tree cost to 266 essence (~34 runs).**
- **Late-game waves keep escalating instead of flattening (iteration 6)** — `waveEnemySpeed` used to hard-cap at 2.4 cells/sec around wave 37, and `waveEnemyCount`/`waveEnemyHp`'s purely linear growth never picked up the slack, so total pressure plateaued right where a run got deepest. All three curves now share that same wave-37 breakpoint: waves 1-37 play identically to before, but past it speed keeps climbing (much more slowly, no hard ceiling) and count/hp both pick up an accelerating term instead of staying flat.
- **The run keeps going in the background (iteration 2).** Iteration 1 auto-paused on losing window focus; Yev's feedback was that it should keep running unless he explicitly taps ⏸ or opens a menu (help/Upgrades) — so iteration 2 removed the auto-pause.
- **Help (❓) opens directly, no intermediate pause screen (iteration 4).** Previously tapping ❓ called the same `pauseGame()` as the explicit ⏸ button, which showed the "Paused / Resume" card, with the help card then stacked on top of it — so the pause screen was what the player actually saw first. Now ❓ pauses state directly and opens the help card with nothing underneath to dismiss; tapping anywhere on the card's backdrop closes it and resumes (only if the run had actually been live when help was opened — reopening ❓ while already paused via ⏸ won't un-pause on close).
- **💣 Bomber enemy (iteration 5 revision), mixed into wave spawns from wave 6 onward** (chance ramping `min(0.15 + (wave-6)*0.03, 0.5)` — 15% at wave 6, capping near 50% by wave ~20 — same formula the original Breaker used, just renamed). Same wall/pathing rules, HP, and speed as the regular enemy, and it keeps the same guaranteed-open-path guarantee every enemy gets (`wouldSeal()` no longer exempts it — that exemption was the original Breaker's whole mechanic, and it's gone). Instead it carries a fuse, captured at spawn and shorter at later waves (`max(4, 9 - (wave-6)*0.15)`, floored at 4s): a filling ring around it fills in and pulses faster as the fuse burns down, reading as increasingly urgent. Left alone until the fuse hits zero, it detonates — flat 30 damage (no falloff) to every tower within 1.5 cells, a particle burst, a radius-flash, and a distinct explosion sound — then is consumed (no leak, no kill-gold, since the player didn't kill it). Killed by towers before the fuse expires, it just dies normally like any other enemy, no explosion. This replaces the original Breaker's "get walled in, then attack" mechanic, which playtesting found unreachable in a normal maze — the Bomber's threat doesn't depend on maze shape at all.
- **Towers have HP (iteration 5), didn't before.** Per-level values: 🟦 Spire 40/55/75, 🟪 Prism 55/70/90, 🟡 Volt 25/35/45 (rank 1→3). Only a Bomber's blast can damage a tower — upgrading fully repairs it to the new level's hp. A damaged tower shows a red-tinted color and an hp bar; both stay hidden at full health so undamaged towers look exactly as before.
- **Same board on mobile and laptop.** The 8×14 grid aspect (~0.57) was chosen to closely match a phone's usable portrait area; on wider screens the identical board centers with even matting on both sides rather than stretching — the same device-parity approach Black Hole in One uses (fixed course, letterboxed into any viewport).

## Design decisions and why

- **Flow-field pathfinding, not per-enemy path arrays** — a single BFS distance field from the core (recomputed only when a wall is placed/sold) lets every enemy just greedy-step toward the neighboring cell with the lowest distance. This is what makes rerouting mid-wave robust for free: no enemy can ever end up on an unreachable cell as long as build validation checks reachability for the spawn cell *and* every currently-active enemy's cell (not just spawn), which is exactly what `wouldSeal()` does.
- **Grid aspect chosen for phone fill, not the concept doc's literal "9×11"** — the concept note suggested ~9×11 as a rough size; building it out surfaced that 9×11 (aspect 0.82) leaves a lot of empty matte on a typical phone (measured ~62% vertical fill at 375×812). 8×14 (aspect 0.57) fills ~89–97% of the board area on both a phone and a centered desktop viewport without changing the maze-building feel — same BFS/flow-field logic, just more room to build a longer corridor.
- **Core-loop-only iteration 1 (Yev's scope call, in chat)** — the questionnaire's own Q10 recommended shipping a minimal meta-tree in the very first jam ("the meta *is* the hook; without it you can't judge the fusion"). Yev asked for an even tighter first ship instead: prove the maze mechanic alone is fun before adding the roguelike layer, so a meh/keep verdict on iteration 1 is unambiguously about the maze-building feel, not muddied by an undertuned meta-tree shipped in the same pass.
- **Manual "Start Wave" instead of an auto-timer** — keeps the between-wave planning phase genuinely pressure-free, matching the design note's "board fully at rest between waves" goal and the arcade's general pause-friendly preference.
- **WebAudio synth SFX, no assets** — build/upgrade/sell/shoot/hit/death/leak/wave-clear/game-over all get a short oscillator blip, matching the "looks and sounds cool" bar other Lab jams hit without an art/audio budget.
- **Auto-pause removed, iteration 2** — iteration 1 matched the Flow Glider/Black Hole in One pattern of auto-pausing on blur/hidden/pagehide. The verdict questionnaire's free space asked for the run to keep going in the background; pause is now only ever explicit (⏸ button or opening a menu).
- **Mirror overlay swallowing board taps, fixed at the root cause, iteration 2** — the verdict questionnaire's "can't build during a run, need to click off a tile and back on" wasn't actually a phase gate (nothing blocked building on `phase==='wave'`). The real cause: the build/tower-action sheet's full-screen backdrop absorbed the tap meant for a newly-selected cell when switching selection with a sheet already open, closing the old sheet but eating the new tap. Fixed by routing a backdrop tap over the board straight into the same cell-selection handler.
- **Tower balance retuned + Volt Coil added, iteration 2** — Q4 flagged Pulse Spire and Frost Prism as indistinguishable. Spire pushed further into long-range single-target focus fire; Prism pushed further into short-range, bigger-splash, heavier-slow crowd control (trading away some damage). Volt Coil, unlocked via the Mirror, is a third archetype (cheap/rapid/low-damage chip) rather than a reskin of the other two.
- **Mirror node list adapted from Improvements.md, iteration 2** — the candidate list in [ideas](ideas.md) included a "draft re-roll" node, but iteration 2 has no draft-1-of-3 system to re-roll. Substituted ⚡ Overcharge (+damage) instead, for a direct "stronger every run" power feeling; the other four nodes (Deep Pockets, Fortified Core, Cheap Walls, Volt Coil unlock) match the candidate list as proposed.
- **Iteration 3 is presentation-only, no economy/combat numbers touched** — Yev's direct ask was clarity and less text, not new systems, so nothing in `TOWER_DEFS`/`META_NODES`/wave-scaling formulas changed value, only their copy and how they're surfaced. Keeps the iteration tightly scoped (per the jam-iteration convention) rather than bundling in the questionnaire's separate Q5 picks (second enemy type, further balance tuning).
- **Range ring shown only on an already-built tower's action sheet, not while choosing what to build** — showing a live preview ring per build-sheet option would need a hover/select-then-place interaction model (the sheet currently builds directly on tap); deferred as a bigger UX change than a polish pass, captured in Improvements.md.
- **Locked tower shown, not hidden** — an invisible 3rd tower is indistinguishable from a missing/broken one; a visibly locked slot with a stated unlock path reads as "not yet" instead. This generalizes past Volt Coil: any future Mirror-gated content should default to "shown locked," not "hidden until earned."
- **Wave-progress total computed from the existing `waveEnemyCount(wave)` formula rather than new counters** — since `enemiesToSpawn` was already seeded from that same function at wave start, `resolved = total - (enemies.length + enemiesToSpawn)` falls out for free; no new state, no new failure mode to keep in sync.
- **Help pause tracked with a `helpWasRunning` flag rather than reusing `pauseGame`/`resumeGame`, iteration 4** — the explicit ⏸ button's pause/resume pair always shows/hides `pauseOverlay`, which is exactly the screen help needed to *not* show. Rather than parameterize `pauseGame()`, help gets its own `openHelp()`/`closeHelp()` pair that sets `state.paused` directly and remembers whether the run was actually live when help opened, so closing only resumes a run that help itself paused — not one already paused via ⏸, and not the initial-boot howto card in a way that would fight `resetGame()`'s own state.
- **Sheet capped with `max-width` + `margin: 0 auto`, not restructured, iteration 4** — Q3 offered a heavier bottom-bar redesign (option B) and a lighter max-width constraint (option C); Yev picked A (match mobile proportions exactly), which the existing `left:0; right:0; bottom:0` positioning already supports by simply adding a cap and auto margins — no layout model change.
- **"Upgrades" over "Warden's Cache"/"Ascension," iteration 4** — Q4's other options kept some thematic framing; Yev picked the fully lore-light option, so the rename drops fantasy/scrying language entirely rather than reskinning it, matching the abstract/neon look the rest of the game already committed to (Q9=D).
- **Breaker's `wouldSeal()` exemption reverted, iteration 5 revision** — the original Breaker design exempted itself from the reachability check so a player could deliberately wall it in (`cellOccupiedActiveEnemies(excludeBreakers)`). Yev's own playtest ("I see the new units but I can't make a blocking path") found that unreachable in practice: `wouldSeal()` also unconditionally protects spawn's own route to the core, and a normal single-corridor maze has only one route — trapping a Breaker required a redundant loop/fork the game never teaches and nobody naturally builds. The fix wasn't a better trapping mechanic; it was dropping the whole "trapped enemy" premise. `cellOccupiedActiveEnemies()` is back to taking no arguments, unconditional for every enemy again — topology no longer matters for this mechanic at all.
- **Fuse-based self-destruct instead of blocked-detection, iteration 5 revision** — replaces `findAdjacentTowerToAttack()`'s nearest-tower BFS and the blocked-timer/attack-key state entirely. A Bomber's fuse is captured once at spawn from `bomberFuseSeconds(wave)` and just counts down every frame regardless of what the maze looks like or whether the Bomber ever gets stuck — no distance-field check, no BFS, no per-target state. This is what makes the mechanic work in *any* maze shape, the whole point of the revision.
- **Detonation collects towers into a list before mutating state, iteration 5 revision** — `detonateBomber()` scans `state.towers` for everything within blast radius, damages/destroys from that snapshot afterward, rather than damaging-while-scanning. `destroyTower()` deletes entries from `state.towers` mid-loop; iterating a live object while deleting from it is exactly the kind of bug that only shows up with 3+ towers in range at once, so the snapshot isn't defensive-programming, it's the only correct way to do it here.
- **Flat 30 damage, no falloff, matching Frost Prism's existing splash style, iteration 5 revision** — rather than inventing a new falloff curve, the Bomber's blast reuses the "flat damage within radius" shape the game already has (Frost Prism's AoE), just with a bigger radius (1.5 cells) and no slow. Keeps the mental model consistent: AoE in this game means "everything in the circle takes the same hit."
- **Upgrading a tower fully repairs it (kept from the original Breaker design)** — matches how dmg/range already reset to the new level's values rather than accumulating/carrying forward partial state. Still means upgrading a nearly-destroyed tower is a valid escape from a Bomber's incoming blast — still an open question in Improvements.md in case that reads as too strong once played.
- **Destroyed towers give no refund (kept from the original Breaker design)** — distinct from selling (60% refund, a deliberate player choice); a Bomber-destroyed tower is a wall that got blown up, not removed on purpose. Also still an open question in case a smaller partial refund would feel better.
- **Wave 6 start / 15%→50%-by-wave-20 spawn ramp unchanged, fuse-length-by-wave new, iteration 5 revision** — the spawn-chance ramp (`bomberChance`, same formula as the old `breakerChance`) wasn't part of what broke, so it carried over untouched. The fuse itself is a new knob Yev asked for directly ("shorter fuse at higher waves, more urgency late-game"): `max(4, 9 - (wave-6)*0.15)`, 9s at wave 6 down to a 4s floor around wave 39 — a first-guess number like every other wave-scaling knob, flagged for iteration 6's retune pass.
- **Ranks 1-3 of the four original Upgrades nodes kept their exact cost/effect, iteration 6** — rather than re-balance the whole curve, extending 3→5 ranks only added new tiers on top (ranks 4-5), on the same cost-growth ratio ranks 1-3 already used. Anything Yev had already banked into the tree before this shipped keeps meaning exactly what it always meant; only the ceiling moved.
- **Reinforced Walls added as a 6th node rather than folded into an existing one, iteration 6** — tower HP had no Upgrades lever at all (only Overcharge, which helps kill a Bomber faster, and Cheap Walls, which helps afford rebuilding) despite being a real stat since iteration 5's tower-HP addition. `effectiveHp()` mirrors `effectiveDmg()`/`effectiveCost()` exactly — same multiplier pattern, applied at tower placement and on upgrade (which still fully repairs, now to the boosted max).
- **One shared breakpoint for all three late-wave curves, iteration 6** — rather than three independently-tuned cutoffs, `LATE_WAVE_START` is defined once as the old speed-cap wave (`Math.round((2.4-1.1)/0.035)` = 37) and all three formulas branch on it. Keeps waves 1-37 byte-for-byte identical to every prior iteration (nothing before that wave changes), and gives the late game a single, legible "this is where it ramps up" moment instead of three uncoordinated thresholds.
- **Speed eases off rather than staying hard-capped, iteration 6** — a permanent flat 2.4 cells/sec ceiling was the actual bug (enemies stop getting faster forever); rather than remove the cap outright (which could make late waves unreadably fast), it now keeps rising at 0.01/wave past 2.4 — enough to keep contributing to the escalation without spiraling.
- **`effectiveCost()` grew a second parameter rather than a parallel function, iteration 7** — `isInitialBuild` gates the new inflation multiplier on top of the existing `cheapWalls` reduction, so `placeTower()` and the build-sheet display both opt in with `true` while `upgradeTower()` and the upgrade-sheet display keep calling it with one argument, unaffected. One function, one source of truth for "what does a tower cost right now," instead of two cost functions that could drift out of sync.
- **No new field needed for the sell-refund correctness gotcha, iteration 7** — the scoping worry was that selling an old cheap tower late-game could refund more than it cost if the refund were recomputed from the current (higher) multiplier. `tower.spent` already existed (accumulating actual gold paid across build + every upgrade) and `sellTower()` was already refunding 60% of *that*, not a recomputed cost — so the fix was confirming the existing field already closes the gap, not adding a `tower.builtCost` field that would have duplicated it.
- **Bomber tower-damage bug fixed with no code change, iteration 7** — root-caused via a debug hook (undefended Bomber near towers at different HP: damage, destruction, and the tint/hp-bar visuals all applied correctly) and a live multi-wave simulation of natural play (a Bomber's HP equals a grunt's, so tower fire in a well-defended maze reliably kills it in ~1-2s versus a 9s+ fuse — but the same simulation caught a real detonation landing on a tower for the expected 30 damage when one did survive). The mechanic works exactly as designed; it's just rare enough in practice that Yev's few Bomber sightings never happened to include one surviving to blow up. Bomber HP/frequency retuning to make detonations more common was explicitly out of scope this round (Q3=A).

## Known simplifications / cut scope

Iteration 2 shipped the meta-progression tree, persistence (`localStorage`), and the tower-balance/pause/build fixes. Iteration 3 shipped the speed toggle, range-ring preview, locked-tower discoverability, wave-progress bar, and a copy trim — presentation only, no new systems. Iteration 4 shipped the help/pause modal fix, the desktop sheet-width cap, and the Mirror → Upgrades rename — bugfix/wording only, no economy or combat numbers touched. Iteration 5 shipped a second enemy type and tower HP; its original 🧨 Breaker (blocked-then-attack) turned out unreachable in a normal maze and was replaced same-day by the 💣 Bomber (fuse-based self-destruct) — tower HP, the damaged-tower visual state, and `destroyTower()` all carried over unchanged. Iteration 6 shipped a deeper Upgrades tree (5-rank caps, a new 6th tower-HP node) and an un-flattened late-game wave curve — numbers-only, no new systems. Iteration 7 shipped escalating tower-cost inflation as a late-game gold sink and root-caused (no code change) a Bomber tower-damage bug report. Still cut, captured as checkboxes in [Improvements](ideas.md): only two enemy archetypes now (Bomber shipped; Runner/Tank/Splitter parked as a later variety pass), no best-score/high-wave tracking, no draft-1-of-3, no hero ability, no voluntary Heat/Pact difficulty knob, no hex grid mode, no lane offset for enemies overlapping on the same corridor, no range-ring preview while choosing what to build (only on an already-built tower), the Bomber's own knobs (start wave, spawn ramp, fuse-length curve, blast radius/damage) are still first-guess and untouched by iteration 6's retune, the "solved maze / nothing left to think about" half of the too-easy complaint is still unaddressed (deliberately deferred, Q3=A), EN-only.

All three iterations scoped by [Iteration 4 Direction](../../archive/questionnaires/maze-warden-iteration-4-direction.md) (4, 5, 6) are now shipped. Yev's own many-wave playtest read of iteration 6 landed the same day: **Meh**, overriding the provisional agent-verified **keep** — the tree/curve depth wasn't the fix, because the actual "maxes out fast / nothing to spend money on" complaint traces to the **in-run gold economy**, which iteration 6 never touched (a maxed maze has a fixed, low-thousands gold ceiling; per-wave income grows faster than linear past it, so late-game gold just sits unused).

**Iteration 7 shipped the same day** (answered + shipped 2026-07-21, commit `47c6654`, deploy verified via Pages): escalating tower-cost inflation as the gold sink (Q2=A) — a run-scoped `towersBuiltThisRun` counter feeds a `1 + 0.05×` multiplier into the cost of every *new* tower placement only (upgrades and sell refunds are unaffected, verified live via the actual build/upgrade/sell UI) — plus the bundled Bomber-damage bug Yev flagged in the same pass ("I don't see the towers being damaged"). That bug **root-caused as working-as-intended, not a defect**: a debug-hook test confirmed `detonateBomber()`'s damage application and the scorched-tint/hp-bar visuals are all correct, and a live multi-wave simulation showed *why* Yev never saw it — a Bomber's HP equals a regular grunt's, so tower fire in any maze dense enough to survive escalating waves reliably kills it before its fuse expires; the mechanic did fire correctly on the rare Bomber that survived long enough. No code change was needed for the bug. Full verification detail and the shipped-vs-scoped diff: [Improvements](ideas.md).
